MegaCalc.

One calculator that refused to stay one calculator — standard, scientific, unit converter, graphing — all keyboard-first, all local.

RoleDesign, build, deploy — solo
StackVanilla JS · Canvas · Vercel
StatusLive, still growing
TimelineGrown since 2025

The problem

The calculators that ship with your OS haven't improved in a decade. The web ones are worse — ads everywhere, one button per click, and the moment you need a unit conversion you're off to a different site with three popups.

The goal sounds small: one tab, everything computational. Standard and scientific modes, a unit converter, a graph, running history — no ads, no accounts, no waiting. And it had to feel right to a keyboard user: Enter equals, Esc clears.

The build

MegaCalc is deliberately vanilla — no framework, no dependencies. The four modes share one expression core; the graph is raw Canvas drawing expressions sampled per pixel column; every preference (theme, angle mode, history) persists to localStorage so the calculator you left is the calculator you return to.

  • A real parser — expressions run through a tokenizer and shunting-yard evaluator, not eval(). Operator precedence, unary minus, and the classic -3² cases all behave like real math.
  • Canvas graphing — pan and zoom by dragging; expressions re-sampled per frame, so the graph is as smooth as the buttons.
  • Zero-backend — everything computes on-device. It works on a plane, and it'll still work in ten years.

What went wrong first

Version one used eval(). It took four lines and broke on everything that matters: 0.1+0.2 floated wrong, expressions like 2(3+4) crashed, and any input was arbitrary code execution waiting to happen. Rebuilding on a tokenizer took three days and taught me more about language design than any tutorial — you can't fake operator precedence; you have to implement it.

What I learned

Small tools deserve real engineering. Nobody's impressed by a calculator's feature list — they're impressed when 2+2×3 comes out as 8 and the thing never lags. Precision, keyboard handling and persistence are the whole product. That mindset — sweat the invisible details — is what I now bring to every project.
